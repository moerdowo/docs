## Authorization

  Example:

  `Authorization | Bearer Paste-Your-API-Key-Here`

## Query Parameters

<ParamField query="customerId" type="string" required>
  The unique identifier of the customer whose credit balance is being queried.
</ParamField>

<ParamField query="productId" type="string" required>
  The unique identifier of the product associated with the credit balance.
</ParamField>

## Response

Successful Response

### Main Structure (Root)

<ResponseField name="statusCode" type="integer">
  Status code from API.
</ResponseField>

<ResponseField name="message" type="string">
  Status message that describes the status code (`"success"` on success).
</ResponseField>

<ResponseField name="data" type="object">
  Object containing the customer's credit balances.
</ResponseField>

### data Structure (Object)

<ResponseField name="customerBalance" type="float">
  Total credit balance (sum of `MAIN` and `ADD_ON` balances).
</ResponseField>

<ResponseField name="customerBalanceMain" type="float">
  Credit balance with `MAIN` type.
</ResponseField>

<ResponseField name="customerBalanceAddon" type="float">
  Credit balance with `ADD_ON` type.
</ResponseField>

### Errors

<ResponseField name="400 Bad Request" type="object">
  Returned when a required parameter is missing or invalid. Validation errors use
  the PLURAL `messages` key with the error details in `data`:
  `{ "statusCode": 400, "messages": "Validation Error", "data": [ ... ] }`.
</ResponseField>

<ResponseField name="500 Internal Server Error" type="object">
  Returned on an unexpected server error:
  `{ "statusCode": 500, "message": "..." }`.
