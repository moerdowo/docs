## Authorization

  `Authorization | Bearer Paste-Your-API-Key-Here`

## Request Body

<ParamField body="customerId" type="string" required>
  The unique identifier of the customer whose credit will be spent.
</ParamField>

<ParamField body="productId" type="string" required>
  The unique identifier of the product associated with the credit.
</ParamField>

<ParamField body="amount" type="integer" required>
  The amount of credit to deduct (positive integer).
</ParamField>

## Response

Successful Response

<ResponseField name="statusCode" type="integer">
  Status code from API.
</ResponseField>

<ResponseField name="message" type="string">
  Status message describing the outcome. On success it reports the spent amount
  and how it was split across wallet types, e.g.
  `"Successfully spent 10. MAIN: 10, ADD_ON: 0"`.
</ResponseField>

### Errors

<ResponseField name="400 Bad Request" type="object">
  Returned when the customer does not have enough credit:
  `{ "statusCode": 400, "message": "Cannot spend customer credit. Insufficient customer credit" }`.
  Note the singular `message` key.
</ResponseField>

<ResponseField name="400 Validation Error" type="object">
  Returned when a required body parameter is missing or invalid. Validation errors
  use the PLURAL `messages` key with the error details in `data`:
  `{ "statusCode": 400, "messages": "Validation Error", "data": [ ... ] }`.
</ResponseField>

<ResponseField name="500 Internal Server Error" type="object">
  Returned on an unexpected server error:
  `{ "statusCode": 500, "message": "..." }`.
</ResponseField>
