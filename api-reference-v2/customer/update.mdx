{/* Notes for maintainers: this is a WRITE endpoint — to avoid mutating live
    merchant data, the response example below is REPRESENTATIVE, derived from the
    V2 customer-update endpoint. IMPORTANT: the customer to update
    is selected by the `{uuId}` PATH segment (= the source customer
    id); the new email is the `toEmail` body field (its only
    field). There is NO `fromEmail` body field in V2 — that was the V1 shape. When
    `toEmail` already belongs to another customer the handler migrates balance and
    transaction history to it and archives the source customer. `messages` is PLURAL.
    All values are synthetic. */}

<RequestExample>

```bash Request Example
curl --request POST 'https://api.mayar.id/hl/v2/customers/a1b2c3d4-e5f6-4789-a012-3456789abcde/update' \
--header 'Authorization: Bearer Paste-Your-API-Key-Here' \
--data-raw '{
    "toEmail": "budi.santoso.new@example.com"
}
'
```

</RequestExample>

<ResponseExample>

```json Response Example 200
{
    "statusCode": 200,
    "messages": "success"
}
```

</ResponseExample>

Endpoint:

<CodeGroup>

```Production Production
https://api.mayar.id/hl/v2/customers/{uuId}/update
```


```Sandbox Sandbox
https://api.mayar.club/hl/v2/customers/{uuId}/update
```

</CodeGroup>

<Note>
  The customer to update is selected by the `{uuId}` segment in the URL **path** —
  this is the source customer id (the `id` returned by the customer list/detail
  endpoints). The request body carries only the new email in `toEmail`.
</Note>

## Authorization

<ResponseField name="Authorization" type="string" required>
  Example:

  `Authorization | Bearer Paste-Your-API-Key-Here`
</ResponseField>

## Path Parameters

<ParamField path="uuId" type="string<uuid>" required>
  The id of the customer whose email is being changed (the source customer id).

  Example:

  `a1b2c3d4-e5f6-4789-a012-3456789abcde`
</ParamField>

## Request Body

<ParamField path="toEmail" type="string" required>
  The new email address for the customer.
</ParamField>

## Response

Successful Response

### Main Structure (Root)

<ResponseField name="statusCode" type="integer" >
  Status code form API.
</ResponseField>

<ResponseField name="messages" type="string" >
  Status message that describes the status code.
</ResponseField>

## Errors

<ResponseField name="400 Validation Error" type="object">
  Returned with `messages: "Validation Error"` when the request body fails
  validation (e.g. missing or malformed `toEmail`).
</ResponseField>

<ResponseField name="404 Customer Not Found" type="object">
  Returned with `messages: "Customer not found"` when no customer matches the
  `{uuId}` path segment.
</ResponseField>
